# Next.js + Supabase starter

A product-neutral starter for server-rendered web apps: Next.js App Router, React, strict TypeScript, Tailwind CSS, Supabase Auth and Postgres with Row Level Security, Drizzle ORM, English/Spanish localization, accessible forms, Storybook, and a CI pipeline that runs entirely on local services.

Everything runs locally with Docker. No paid account, hosted project or API key is needed for development, tests, CI or production builds.

## What is included

- **Next.js 16** App Router on the Node.js runtime, React 19, React Compiler (production builds), Tailwind CSS 4
- **Supabase Auth** with `@supabase/ssr`: email/password sign-up, sign-in, sign-out, password reset via email links that work on any device, session refresh in `src/proxy.ts`, protected `/app` area
- **Supabase Postgres + Drizzle ORM**: schema and RLS policies in `src/models/Schema.ts`, migrations generated by Drizzle Kit and applied by the Supabase CLI, queries run as the signed-in user through `withRls()`, pgTAP and Vitest RLS tests
- **Forms**: React Hook Form with Zod schemas shared by the browser and Server Actions; works without JavaScript
- **next-intl** with `en` (default) and `es`, checked-in dictionaries and automated key checks
- **Accessible UI**: semantic shell with skip link and landmarks, labelled forms with linked errors, language links, axe checks in Storybook and E2E
- **Security defaults**: server-side authorization plus RLS, no user-supplied redirect targets, Zod validation at boundaries, baseline security headers, log redaction
- **Optional Sentry**, disabled unless a DSN is set, with privacy-conservative settings
- **Quality tooling**: Oxlint/Oxfmt (Ultracite presets), Knip, i18n-check, Vitest (Node, browser and story tests), Storybook, Playwright, Lefthook, commitlint, npm-run-all, GitHub Actions, semantic-release, Dependabot

Not included on purpose: analytics, consent UI, file uploads, background jobs, branded or localized emails (only the two auth link templates exist), payments or any product domain. See [`docs/decisions/`](docs/decisions/) for how to add them.

## Prerequisites

- Node.js 24+ and npm 11+
- Docker (Docker Desktop on Windows/macOS, or Docker Engine on Linux) for the local Supabase stack
- About 4.5 GB of disk for Supabase images (Postgres and Studio are about 1.7 GB each); the first `npm run db:start` takes a few minutes

## Quick start

```shell
npm ci
cp .env.example .env.local
npm run db:start
npm run dev
```

Open http://localhost:3000. Local services:

| Service | URL |
|---|---|
| App | http://localhost:3000 (`/es` for Spanish) |
| Storybook (`npm run storybook`) | http://localhost:6006 |
| Supabase API | http://127.0.0.1:54321 |
| Supabase Studio | http://127.0.0.1:54323 |
| Mailpit (captured auth emails) | http://127.0.0.1:54324 |
| Postgres | `postgresql://postgres:postgres@127.0.0.1:54322/postgres` |

`.env.example` already contains the fixed local Supabase URL, publishable key and database URL. If `npm run db:start` prints different values, copy them into `.env.local`.

Stop the stack with `npm run db:stop`.

## Authentication demo

| Route | Purpose |
|---|---|
| `/sign-up` | Create an account. Locally, email confirmation is off, so you are signed in immediately. |
| `/sign-in` | Email and password sign-in |
| `/forgot-password` | Sends a reset link. Locally it appears in Mailpit. The link opens `/auth/confirm`, which works in any browser |
| `/app` | Protected page: signed-in email and an editable display name stored in `profiles` (Drizzle + RLS) |
| `/app/update-password` | Change password (also the target of reset links) |

All routes also exist under `/es/...`.

**Registration in production is your decision.** The local config allows public sign-up without email confirmation for convenience. For a hosted project, configure in the Supabase dashboard: whether sign-up is allowed, email confirmation, an SMTP provider, CAPTCHA, rate limits and allowed redirect URLs. Set the Site URL to `NEXT_PUBLIC_APP_URL` and allow `<NEXT_PUBLIC_APP_URL>/**`: otherwise Supabase replaces the confirm page URL in the email templates with the Site URL, and email links open the home page without signing anyone in. Hiding the sign-up link does not stop API sign-ups. See [docs/architecture.md](docs/architecture.md#registration-policy-decide-per-product).

## Database workflow

```shell
# 1. Edit tables and RLS policies in src/models/Schema.ts
npm run db:generate -- --name=add_something           # writes supabase/migrations/<timestamp>_add_something.sql
# 2. Grants, triggers or extensions Drizzle cannot express:
npm run db:generate -- --custom --name=add_something_grants
# 3. Apply and test
npm run db:migrate                                    # or npm run db:reset to replay everything
npm run test:rls                                      # add pgTAP tests in supabase/tests/database/
npm run test:db
```

Commit the generated SQL **and** `supabase/migrations/meta/`. New tables are **not** exposed to the Data API automatically (`auto_expose_new_tables = false`); grant access explicitly.

Query data only through `withRls(claims, (tx) => …)` from `@/libs/DB`. It runs the queries in a transaction as the `authenticated` role with the user's verified JWT claims, so RLS applies. The underlying `DATABASE_URL` connection is privileged.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Local default in `.env.example` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Yes | Publishable (client-safe) key, not the secret key |
| `DATABASE_URL` | Yes | Server-only Postgres connection for Drizzle. Secret in hosted environments; use the Supabase pooler connection string |
| `NEXT_PUBLIC_APP_URL` | Yes | Public base URL for auth email links, sitemap and robots. Local default in `.env.example`; set the real URL in production |
| `NEXT_PUBLIC_LOGGING_LEVEL` | No | `trace`, `debug`, `info` (default), `warning`, `error`, `fatal` |
| `NEXT_PUBLIC_SENTRY_DSN` | No | Enables Sentry when set |
| `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN` | No | Build-time source map upload; keep the token secret |

All variables are validated in `src/libs/Env.ts`. `NEXT_PUBLIC_*` values are inlined at build time, so set them before `npm run build`.

## Testing

```shell
npx playwright install chromium   # once, for component, story and E2E tests
npm test
npm run test:storybook
npm run db:start                  # needed by the next three commands
npm run test:rls
npm run test:db
npm run test:e2e
```

Or run `npm run verify` for everything. E2E tests create throwaway users in the local database and read reset emails from Mailpit. No test contacts hosted services.

## Continuous integration and releases

`.github/workflows/CI.yml` runs on pull requests and pushes to `main`, with no repository secrets:

- **Static checks**: commit messages (PRs), typecheck, lint, format, Knip, i18n, `npm audit` (production deps block on high, all deps block on critical, full report printed), `npm audit signatures`
- **Unit, component and story tests** in Node and headless Chromium
- **Production build** and static Storybook build
- **Integration**: local Supabase, pgTAP RLS tests, Drizzle RLS tests, schema/migration drift check, Playwright (Chromium and Firefox)

`.github/workflows/release.yml` runs semantic-release after a successful CI run on `main`: it creates a version tag and GitHub release from Conventional Commits using the built-in `GITHUB_TOKEN`. Nothing is published to npm.

Git hooks (Lefthook) check formatting, lint and commit messages on commit, and run typecheck, Knip and i18n checks on push. They never rewrite files.

## Deployment

The app is a standard Next.js Node.js server (`npm run build && npm start`) and works on Vercel or any Node host or container. Before a real launch, complete the product checklist in [ADR-005](docs/decisions/ADR-005-privacy-and-deployment.md): hosted Supabase configuration, environment variables (including `NEXT_PUBLIC_APP_URL` and a pooled `DATABASE_URL`), email delivery with the templates from `supabase/templates/`, backups, monitoring and a nonce-based CSP. Apply migrations to hosted projects with the Supabase CLI (`supabase db push`).

## Known limitations

- No script/style Content Security Policy yet (needs nonces; see [architecture](docs/architecture.md#security-defaults)).
- Application mutations are not rate limited; Supabase Auth has its own limits.
- Translations are maintained by hand; the Spanish copy has not been reviewed by a native speaker.
- Accessibility is covered by automated axe checks and keyboard tests, not by manual screen reader audits.
- Accepted dev-only audit findings: npm's bundled `undici`/`ip-address` (installed with semantic-release, unfixed upstream) and `drizzle-kit`'s bundled `esbuild` (moderate). See [cleanup-audit.md](docs/cleanup-audit.md#owner-requested-reintegration).
- Next.js 16.4 dev server bug: several simultaneous first requests to localized pages can corrupt `.next/dev/prerender-manifest.json`, after which `next dev` answers 500 (`Unexpected non-whitespace character after JSON`) until restarted ([vercel/next.js#96664](https://github.com/vercel/next.js/issues/96664), fix in [#100521](https://github.com/vercel/next.js/pull/100521)). Restart `npm run dev` if it happens. Production servers and the E2E suite (which uses `next start`) are not affected.
